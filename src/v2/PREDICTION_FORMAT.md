# Prediction schema, version 2 (P2-A)

**Status:** frozen 2026-09-03. Any change to this file must be announced to P2-A, P2-C and P2-D
before it is made, because predictions written against an older version cannot be pooled with
predictions written against a newer one.

**Applies to:** every model family in the re-analysis, including the deep families owned by P2-C
(`deephit`, `nfg`). It replaces `src/models/README.md` and `src/models/io_utils.py`, which wrote a
single complete-case prediction file per model. Version 2 writes one file per model per split per
imputation, because multiple imputation is now the primary analysis.

Version 1 outputs in `results/predictions/` are the prior attempt. Do not overwrite them and do not
read them into the version 2 pipeline.

---

## 1. Input the models are fitted on

`data/processed/imputed/imp_<k>.parquet`, k = 1..30. Each file is one completed dataset: the full
mortality-eligible cohort, **N = 41,151 rows**, one row per respondent, no missing values in the 11
predictors. Files are byte-stable given seed 20260903 and are regenerated by `src/v2/01_impute.R`.

Do **not** re-filter, re-split or re-fold. Every column needed to reproduce the design is in the
file.

### Columns of `imp_<k>.parquet`

| column | type | meaning |
|---|---|---|
| `SEQN` | int64 | respondent id, the join key across every file in the pipeline |
| `cycle` | string | NHANES 2-year cycle label, e.g. `2007-2008` |
| `cycle_startyr` | int64 | 1999 .. 2017 |
| `age` `sex` `sbp` `antihtn` `totchol` `hdl` `statin` `diabetes` `smoke_current` `bmi` `egfr` | float64 | the 11 primary predictors, **imputed, complete**. `sex` is encoded 1 = male, 0 = female. The five binaries take values in {0,1} exactly. |
| `time` | float64 | follow-up years, > 0. See section 2. |
| `event` | int64 | 0 = censored, 1 = CVD death, 2 = competing (non-CVD) death |
| `event_naive` | int64 | 1 iff `event == 1`, else 0. Competing death treated as censoring. |
| `split` | string | `train` (cycle start 1999/2001/2003/2005), `test` (2007/2009), `holdout_later` (2011/2013/2015/2017) |
| `cv_rep0` .. `cv_rep4` | int64 | repeated cross-validation fold ids, 0..4. See section 4. |
| `race` `hba1c` `uacr` | float64 | sensitivity extras, imputed. **Not** in the primary feature matrix. |
| `SDMVPSU` `SDMVSTRA` `WTMEC2YR` | float64 | survey design columns, never missing, carried for the survey sensitivity analysis only |
| `imp` | int64 | the imputation index k, constant within a file |
| `R_miss_any` | int64 | 1 if this row had at least one of the 11 predictors missing before imputation, else 0. Carried so the evaluation can report results by imputation status. |

The 11 predictors, in this fixed order, are the feature vector:

```
age, sex, sbp, antihtn, totchol, hdl, statin, diabetes, smoke_current, bmi, egfr
```

`src/v2/feature_spec.json` holds the same list in machine-readable form plus which features are
continuous (`age, sbp, totchol, hdl, bmi, egfr`) and therefore standardized.

**Standardization rule, unchanged from version 1 and non-negotiable:** the z-score centre and scale
are computed on the **training rows of the fold being fitted** and applied to the held-out rows.
Never on the pooled data. Binary features are not standardized. This property was cleared of leakage
in the version 1 audit and must be preserved.

## 2. Definition of `time`

`time` = `followup_years_exm` (exam to death or censoring) where observed, and
`followup_years_int` (interview to death or censoring) for the 1,680 respondents who were
interviewed but not MEC-examined and therefore have no exam date.

Justification, computed on the 39,471 respondents with both: the interview-to-exam gap has
mean 0.071 y and maximum 0.250 y, so the substitution shifts follow-up by at most 3 months.
The alternative, dropping those 1,680, is not available: they carry 141 CVD deaths (8.0% of all
CVD deaths in the cohort) and all five MEC-derived predictors missing, so dropping them is exactly
the outcome-dependent dropout the re-analysis exists to remove.

`time` is > 0 for every row. Rows are never dropped for time.

## 3. Output: where predictions go and what they contain

```
results/metrics_v2/predictions/<model_name>__<split>__imp<k>.parquet
```

- `<model_name>` from the fixed vocabulary in section 5.
- `<split>` is `temporal` or `cv`.
- `<k>` is the imputation index, **1..30, written without zero padding**: `imp1`, ..., `imp30`.

Example: `results/metrics_v2/predictions/csc_cox__temporal__imp7.parquet`.

### Required columns, in this order

| column | type | meaning |
|---|---|---|
| `SEQN` | int64 | respondent id |
| `cycle` | string | copied through from the input |
| `time` | float64 | copied through, unmodified |
| `event` | int64 | copied through, 0/1/2, unmodified |
| `risk_5` | float64 | predicted probability of CVD death by 5 y, in [0,1], or NaN |
| `risk_10` | float64 | predicted probability of CVD death by 10 y, in [0,1]. **Required, never all-NaN.** |
| `risk_15` | float64 | predicted probability of CVD death by 15 y, in [0,1], or NaN |
| `model_name` | string | constant within the file |
| `family` | string | `naive` or `competing`, constant within the file |
| `learner_class` | string | the concrete learner, constant within the file. See section 5. |
| `imp` | int64 | k, constant within the file, equal to the `imp` of the input |

For `split == "cv"` two further columns are required:

| column | type | meaning |
|---|---|---|
| `cv_rep` | int64 | repeat index 0..2 |
| `cv_fold` | int64 | fold index 0..4, the fold this row was held out in |

No other columns. Column order as listed. Write with `arrow`/`pyarrow` defaults, no index column.

### Row counts

| split | rows per file | which rows |
|---|---|---|
| `temporal` | 9,329 | every row with `split == "test"` (cycles 2007-2008 and 2009-2010), exactly once |
| `cv` | 123,453 | every row of the full cohort once per repeat: 41,151 x 3 repeats |

Every row of the relevant set must be present exactly once (once per repeat for `cv`). Missing rows
break the paired bootstrap, which indexes models against a common `SEQN` list.

### Meaning of `risk_t`, and the asymmetry that is the point of the paper

- **`family == "naive"`**: `risk_t = 1 - S(t)` from a model that treats competing death as
  censoring. This is a cause-specific survival complement, not a cumulative incidence, and it
  structurally overstates absolute CVD risk.
- **`family == "competing"`**: `risk_t` is the predicted CVD cause-specific **cumulative incidence
  function** at t, which accounts for the competing risk.

Both are written on the same [0,1] scale for the same `SEQN`, which is what makes the paired
contrast possible. Do not rescale, clip beyond [0,1], or recalibrate before writing. Recalibration
is an evaluation-stage decision and belongs downstream.

### Horizons

- 5 y and 10 y are estimable in every split.
- 15 y is **not** estimable on the `temporal` split: the test cycles are 2007-2010 and mortality
  linkage ends 31 Dec 2019, so maximum follow-up there is 13.2 y. Write `risk_15` as NaN for
  `split == "temporal"` unless the learner extrapolates, and if it does extrapolate, still expect
  the evaluation to drop it.
- 15 y is estimable on `cv` because the full cohort includes 1999-2006 cycles with up to 20.8 y.
  The evaluation reports 15 y for `cv` only, and always alongside the at-risk fraction.

10 y is the primary horizon.

## 4. The design: temporal split and cross-validation

**Temporal split** (from `split`): fit on `train` (cycles 1999-2000 through 2005-2006,
N = 14,551), predict `test` (2007-2008 and 2009-2010, N = 9,329). `holdout_later` is not used by
the primary analysis.

**Repeated cross-validation** (from `cv_rep0` .. `cv_rep4`): 5-fold, stratified on `event` (0/1/2),
on the full cohort. Fold assignment is a function of `SEQN` only and is therefore **identical across
all 20 imputations and all models**. That is deliberate: it is what allows the pooling to treat
repeat as a nested factor rather than as an independent replicate.

In repeat r, `cv_rep{r}` gives each row its held-out fold id. To produce out-of-fold predictions for
repeat r, fold f: fit on rows with `cv_rep{r} != f`, predict rows with `cv_rep{r} == f`, and stamp
`cv_rep = r`, `cv_fold = f`.

**Repeats 0, 1 and 2 are the analysis.** `cv_rep3` and `cv_rep4` are written into the imputed files
but are not used, and predictions for them must not be written. Three repeats x five folds x 20
imputations is already 300 fits per model family; the marginal information from repeats 4 and 5 does
not justify the node-hours. If you write only some repeats, say so, and never pool a model that has
three repeats with a model that has two: the version 1 evaluation pooled 5 repeats and 2 repeats as
independent rows, which is the pseudoreplication defect this version fixes.

## 5. Model vocabulary

`model_name` and `family` are closed vocabularies. Use exactly these strings.

| `model_name` | `family` | `learner_class` | owner |
|---|---|---|---|
| `logistic` | `naive` | `IPCWLogistic` | P2-A |
| `logistic_cr` | `competing` | `IPCWLogisticCR` | P2-A |
| `cox_naive` | `naive` | `CoxPH` | P2-A |
| `rsf_naive` | `naive` | `RandomSurvivalForest` | P2-A |
| `gbs_naive` | `naive` | `GradientBoostingSurvival` | P2-A |
| `csc_cox` | `competing` | `CauseSpecificCox` | P2-A |
| `fine_gray` | `competing` | `FineGray` | P2-A |
| `rsf_cr` | `competing` | `RandomSurvivalForestCR` | P2-A |
| `deephit` | `competing` | `DeepHit` | P2-C |
| `nfg` | `competing` | `NeuralFineGray` | P2-C |

`learner_class` exists so the evaluation can tell a learner-matched pair from a mismatched one.
The only learner-matched naive/competing pairs in this benchmark are:

- `cox_naive` / `csc_cox` (both a Cox proportional hazards learner). **Primary.**
- `rsf_naive` / `rsf_cr` (both a random survival forest). Secondary.
- `logistic` / `logistic_cr` (both an inverse-probability-of-censoring-weighted binomial
  regression). Secondary. This pair is an addition to the seven families in the original
  plan. Version 1's logistic model built its binary outcome by discarding everyone censored
  or dead of a competing cause before the horizon, which is outcome-dependent selection.
  Replacing that construction with censoring weights fixes the defect, and because the only
  remaining difference between the two models is whether a competing death is censoring or
  an event, it produces a third learner-matched pair. `src/v2/04_fit_py_models.py` states
  the estimand of each.

`cox_naive` / `fine_gray` is reported as a secondary contrast and labelled as differing in the
target of estimation as well as in the handling of competing risks.

`gbs_naive` / `deephit` is **not** a matched pair and must never be presented as one. They share no
learner. In version 1 that contrast reversed the sign of every claim, and the re-analysis reports it
explicitly as a demonstration that the pairing structure carries the result.

## 6. Validator

Run before handing predictions over:

```
${ENV_PREFIX}/crcvd-py/bin/python src/v2/check_predictions.py results/metrics_v2/predictions
```

It checks file naming, column names, order and dtype, the [0,1] range, the row counts and
uniqueness of `SEQN` (per repeat for `cv`), the closed vocabularies, that `imp` matches the
filename, and that `SEQN`, `time` and `event` agree row-for-row with `imp_<k>.parquet`. A file that
does not pass is not in the analysis.

---

## 7. Seeds and reproducibility

Single project seed: **20260903**. Derive a per-task seed deterministically rather than reusing the
project seed everywhere, so that repeated fits are not accidentally correlated:

```
seed = 20260903 + 1000 * imp + 100 * cv_rep + cv_fold
```

for cross-validation fits, and `seed = 20260903 + 1000 * imp` for temporal fits. Record in the
model's own notes which library-level seeding call was used, because R's `set.seed` and
`randomForestSRC`'s own `seed` argument are not the same mechanism.

Record library versions actually used. Do not downgrade a package to match version 1; the version
drift is documented and attributed instead.
