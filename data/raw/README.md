# data/raw provenance

Read-only inputs to the competing-risks CVD methods paper. Nothing in this directory is
generated by the pipeline; everything was downloaded from a public CDC/NCHS endpoint.
Do not edit these files by hand.

## What is here

| Path | Contents | Files |
|---|---|---|
| `nhanes/` | Continuous NHANES SAS transport (XPT) component files, 10 cycles 1999-2000 to 2017-2018, named `<COMPONENT>_<cycle>.XPT` | 121 |
| `mortality/` | NCHS public-use Linked Mortality Files, 2019 release, `NHANES_<start>_<end>_MORT_2019_PUBLIC.dat` | 10 |
| `manifest.csv` | Per-request download record written by `src/data/download.py` | - |
| `verification_20260904.csv` | SHA-256 comparison of every file against a fresh download (the provenance evidence) | - |

Total 131 files, 225 MB.

## Where it came from

**NHANES.** `https://wwwn.cdc.gov/Nchs/Data/Nhanes/Public/{startyr}/DataFiles/{fname}.XPT`,
where `startyr` is the first year of the cycle. Thirteen logical components were requested
per cycle (DEMO, BPX, BPXO, BMX, TCHOL, HDL, GHB, DIQ, SMQ, BIOPRO, ALB_CR, BPQ, RXQ_RX),
140 requests in all. 131 succeeded; 9 are recorded `missing` in `manifest.csv` because the
component does not exist for that cycle (`BPXO`, oscillometric blood pressure, exists only
for 2017-2018). Early-cycle laboratory files carry legacy names, resolved by the candidate
list in `src/data/config.py`: `LAB13`/`L13_B`/`L13_C` for lipids, `LAB10`/`L10_x` for
glycohaemoglobin, `LAB18`/`L40_x` for biochemistry, `LAB16`/`L16_x` for urine albumin.

Because total and HDL cholesterol share one combined lipid file before 2005-2006,
`TCHOL_<cycle>.XPT` and `HDL_<cycle>.XPT` are byte-identical copies of the same source file
for 1999-2000, 2001-2002 and 2003-2004. The 131 files therefore hold 128 distinct contents.
This is intended, not a duplication error.

**NCHS Linked Mortality File.**
`https://ftp.cdc.gov/pub/Health_Statistics/NCHS/datalinkage/linked_mortality/`,
2019 public-use release, one fixed-width file per cycle, 48 characters per record, parsed by
`src/data/mortality.py` using the column specification in `src/data/config.py`. Landing page:
`https://www.cdc.gov/nchs/data-linkage/mortality-public.htm`.

## When it was retrieved, and how that is known

The original download was not timestamped. `manifest.csv` as first written had no date
column, `logs/download.log` records outcomes without dates, and filesystem mtimes
(2026-09-03 12:48) record the transfer from a previous machine rather than the download.
`env/README.md` bounds the original retrieval to on or before 2026-08-01.

**Verified access date: 2026-09-04.** All 131 files were re-downloaded from the URLs above
on 2026-09-04, between 06:32:37Z and 06:35:28Z, into a scratch tree, and both copies were
hashed with SHA-256.

- 131 of 131 files returned HTTP 200.
- 131 of 131 are **byte-identical** to the copies the analysis used.
- No file had moved or disappeared from its original URL.
- No upstream revision was detected. The NCHS linked-mortality directory listing gives a
  last-modified date of 2022-04-26 for all ten mortality files, with sizes matching these
  copies exactly, so the public-use 2019 release has not been re-issued since.

Cite 2026-09-04 as the data access date. The claim rests on the hash comparison, not on
recall: the files served on that date are the files the analysis was run on.

The scratch tree `data/raw_verify_20260904/` was deleted once the hashes were recorded.
`data/raw/` was not modified at any point.

## SHA-256 manifest

Two records, both in this directory:

- `verification_20260904.csv` - one row per file with `file`, `source_url`, `bytes_repo`,
  `bytes_fresh`, `sha256_repo`, `sha256_fresh`, `identical`, `http_status`, `retrieved_utc`.
  This is the authoritative hash record for the files as used.
- `manifest.csv` - the download record. `src/data/download.py` now appends `retrieved_utc`,
  `http_status`, `bytes` and `sha256` to every row, so any future download timestamps and
  hashes itself. The committed `manifest.csv` predates that change and still carries the
  original five columns; it will gain the new columns the next time the download is rerun.

## Reproducing this directory

```bash
export XDG_CACHE_HOME=${CACHE_DIR}
cd src/data && ${ENV_PREFIX}/crcvd-py/bin/python download.py
```

Files already present and larger than 1000 bytes are treated as cached and are not
re-fetched; delete them first to force a true re-download. Verify the result against
`verification_20260904.csv`:

```bash
sha256sum data/raw/nhanes/*.XPT data/raw/mortality/*.dat
```
